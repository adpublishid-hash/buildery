## Daftar Temuan

### BUG-001 — Account takeover customer melalui registrasi member

- Severity: **Critical**
- Status: **Fixed (2 September 2026)**
- Area: Member authentication, checkout, LMS, membership

#### Deskripsi

Checkout, enrollment, dan pembelian membership dapat membuat record `Customer`
tanpa password. Halaman registrasi member kemudian mencari customer berdasarkan
email. Jika record tersebut belum memiliki password, pengguna baru dapat mengisi
password dan langsung mendapatkan member session tanpa verifikasi kepemilikan
email.

Penyerang yang mengetahui email customer dapat mengambil alih record tersebut,
mengubah profil, lalu mengakses membership dan course milik korban.

#### Bukti kode

- `lib/actions/member-auth.ts:54-94`
- `lib/actions/order.ts:210-224`
- `lib/actions/enrollment.ts:89-102`
- `lib/actions/purchase.ts:77-93`
- `app/site/[workspaceSlug]/member/account/page.tsx:50-70`

#### Skenario reproduksi

1. Customer melakukan checkout atau enrollment menggunakan `korban@example.com`.
2. Buka halaman register member pada workspace yang sama.
3. Daftar menggunakan `korban@example.com` dan password baru.
4. Aplikasi memperbarui record customer yang sudah ada dan langsung membuat
   session.
5. Membership dan enrollment customer sebelumnya tampil pada member area.

#### Rekomendasi

- Wajibkan OTP atau verification link sebelum menghubungkan login baru ke
  customer yang sudah ada.
- Jangan membuat session sebelum alamat email terverifikasi.
- Pisahkan proses `register` dan `claim existing customer`.
- Jangan mengizinkan request anonim memperbarui nama atau telepon customer yang
  sudah mempunyai transaksi.

### BUG-002 — Upload form publik memungkinkan stored XSS

- Severity: **Critical**
- Status: **Fixed (2 September 2026)**
- Area: Form builder, file upload, dashboard submission

#### Deskripsi

Validasi upload mempercayai MIME dari request, tetapi ekstensi file output berasal
dari nama file asli. File bernama `.html` dapat dikirim dengan MIME
`application/pdf`, lolos validasi, dan disimpan di bawah `public/uploads` sebagai
HTML.

Ketika admin membuka lampiran, JavaScript dapat berjalan pada origin aplikasi.
Selain itu, seluruh lampiran dapat diakses tanpa autentikasi apabila URL diketahui.

#### Bukti kode

- `lib/actions/form-submission.ts:111-127`
- `lib/actions/form-submission.ts:223-244`
- `components/forms/submission-actions.tsx:386-400`
- `lib/zod.ts:538-545`

#### Skenario reproduksi

1. Buat file `payload.html` berisi JavaScript.
2. Kirim melalui form publik dengan multipart MIME `application/pdf`.
3. Server menerima MIME tersebut, tetapi tetap memakai ekstensi `.html`.
4. Buka link lampiran dari dashboard submission.
5. Browser merender file sebagai HTML pada origin aplikasi.

#### Rekomendasi

- Validasi magic bytes, bukan hanya `File.type`.
- Gunakan allowlist format yang tetap dan paksa ekstensi berdasarkan hasil
  deteksi server.
- Simpan lampiran di storage privat di luar folder `public`.
- Sajikan file melalui endpoint berotorisasi dengan
  `Content-Disposition: attachment`.
- Jika memungkinkan, gunakan domain terpisah tanpa cookie aplikasi untuk file
  pengguna.

### BUG-003 — Broken access control pada LMS

- Severity: **Critical**
- Status: **Fixed (2 September 2026)**
- Area: Course enrollment, lesson access, lesson progress

#### Deskripsi

Halaman `/learn/{enrollmentId}` hanya memeriksa apakah enrollment ditemukan.
Halaman tidak memvalidasi member session, kepemilikan customer, workspace, atau
status enrollment `ACTIVE`.

Server action perubahan progress juga menerima `enrollmentId` secara langsung
tanpa pemeriksaan kepemilikan. Form enrollment anonim bahkan dapat mengembalikan
ID enrollment aktif milik customer lain berdasarkan email yang dimasukkan.

#### Bukti kode

- `lib/actions/enrollment.ts:87-129`
- `lib/actions/enrollment.ts:247-286`
- `app/learn/[enrollmentId]/page.tsx:54-70`

#### Dampak

- Course berbayar dapat diakses tanpa autentikasi yang benar.
- Nama dan email customer dapat terekspos.
- Progress lesson customer lain dapat diubah.
- Enrollment pending atau cancelled berpotensi tetap dapat dibuka jika ID
  diketahui.

#### Rekomendasi

- Wajibkan member session untuk semua lesson non-preview.
- Pastikan `session.customerId === enrollment.customerId`.
- Pastikan workspace session dan enrollment sama.
- Tolak enrollment dengan status selain `ACTIVE`.
- Gunakan helper otorisasi yang sama pada page dan server action progress.
- Hentikan pengembalian enrollment aktif hanya berdasarkan email anonim.

### BUG-004 — Ongkos kirim dapat dimanipulasi dari browser

- Severity: **High**
- Status: **Fixed (2 September 2026)**
- Area: Checkout, RajaOngkir

#### Deskripsi

Nilai `shippingCost`, courier, service, dan data lokasi dibaca langsung dari
`FormData`. Server tidak menghitung ulang quote berdasarkan cart dan konfigurasi
workspace. Pembeli dapat mengubah `shippingCost` menjadi `0` atau nilai lebih
rendah sebelum order dibuat.

#### Bukti kode

- `components/store/checkout-form.tsx:191-217`
- `lib/actions/order.ts:154-205`
- `lib/actions/rajaongkir.ts:106-146`

#### Rekomendasi

- Kirim hanya ID tujuan serta kode courier/service dari client.
- Hitung berat dari produk dan quantity di database.
- Ambil ulang quote di server saat checkout.
- Simpan dan gunakan nilai quote hasil verifikasi server.

### BUG-005 — Payment fail-open ketika Midtrans tidak dikonfigurasi

- Severity: **High**
- Status: **Fixed (2 September 2026)**
- Area: Payment API, Midtrans

#### Deskripsi

Endpoint pembuatan pembayaran tidak memeriksa session atau ownership payment.
Ketika konfigurasi Midtrans tidak lengkap, payment langsung diubah menjadi
`PAID`. Perilaku simulasi tidak dibatasi hanya untuk development/test.

#### Bukti kode

- `app/api/payments/midtrans/create/route.ts:22-45`
- `app/api/payments/midtrans/create/route.ts:61-68`

#### Rekomendasi

- Pada production, gagal secara tertutup apabila konfigurasi Midtrans tidak
  tersedia.
- Izinkan simulated payment hanya ketika `NODE_ENV !== "production"` dan flag
  development eksplisit aktif.
- Ikat payment ke session, cart, member, atau nonce checkout yang ditandatangani.
- Tambahkan rate limit dan audit log.

### BUG-006 — Stored XSS pada FAQ, blog, text, dan columns

- Severity: **High**
- Status: **Fixed (2 September 2026)**
- Area: Page builder, blog

#### Deskripsi

FAQ dan blog merender HTML mentah menggunakan `dangerouslySetInnerHTML`.
Sanitizer untuk text dan columns hanya menghapus tag `<script>` dan event handler
yang memakai tanda kutip. Payload dengan event handler tanpa tanda kutip,
`javascript:` URL, SVG, dan beberapa vector lain masih dapat lolos.

#### Bukti kode

- `components/blocks/faq-block.tsx:187-191`
- `components/blog/post-content.tsx:1-6`
- `components/blocks/rich-html.tsx:1-13`
- `lib/actions/blog.ts:118-129`

#### Contoh payload

```html
<img src=x onerror=alert(document.domain)>
<a href="javascript:alert(document.domain)">Klik</a>
```

#### Rekomendasi

- Gunakan HTML sanitizer berbasis parser dengan allowlist tag dan atribut.
- Sanitasi di server sebelum data disimpan dan lakukan defense-in-depth saat
  render.
- Larang event handler, scriptable URL, SVG aktif, iframe, object, dan style
  berbahaya untuk rich text biasa.
- Pertahankan custom HTML/JavaScript hanya di iframe sandbox terisolasi.

### BUG-007 — Fulfillment pembayaran tidak atomik dan tidak idempotent

- Severity: **High**
- Status: **Fixed (2 September 2026)**
- Area: Payment webhook, inventory, coupon, affiliate

#### Deskripsi

Payment dibaca dan diperbarui dalam operasi terpisah. Dua webhook yang diproses
bersamaan dapat sama-sama melihat status `PENDING`, mengubahnya menjadi `PAID`,
dan menjalankan fulfillment lebih dari sekali.

Pengecekan order `PAID`, update order, pengurangan stok, penggunaan coupon, dan
pembuatan komisi juga belum memiliki jaminan idempotensi lintas transaksi.

#### Bukti kode

- `lib/payments.ts:29-69`
- `lib/payments.ts:98-130`
- `lib/payments.ts:174-199`
- `lib/actions/order.ts:130-150`

#### Dampak

- Stok dapat berkurang dua kali atau menjadi negatif.
- Penggunaan coupon dapat melebihi batas.
- Komisi affiliate dapat terduplikasi.
- Dua order bersamaan dapat membeli stok terakhir yang sama.

#### Rekomendasi

- Gunakan atomic compare-and-set, misalnya update payment hanya jika status masih
  `PENDING`.
- Jalankan status transition dan fulfillment dalam transaksi database.
- Gunakan row locking atau isolation level yang sesuai.
- Tambahkan unique constraint untuk side effect yang harus satu kali, misalnya
  komisi per order.
- Kurangi stok dengan conditional update `stock >= quantity`.

### BUG-008 — Detail order dan PII dapat diakses dengan nomor order

- Severity: **High**
- Status: **Fixed (2 September 2026)**
- Area: Checkout success page

#### Deskripsi

Halaman success mencari order hanya berdasarkan workspace dan nomor order. Tidak
ada pemeriksaan session customer atau token akses. Halaman menampilkan item,
nomor telepon, alamat lengkap, rekening pembayaran, dan recipient notifikasi.

Nomor order hanya menambahkan tiga karakter random dan endpoint tidak mempunyai
rate limit.

#### Bukti kode

- `app/site/[workspaceSlug]/checkout/success/page.tsx:32-49`
- `app/site/[workspaceSlug]/checkout/success/page.tsx:162-193`
- `app/site/[workspaceSlug]/checkout/success/page.tsx:252-285`
- `lib/store.ts:80-87`

#### Rekomendasi

- Wajibkan member session yang memiliki order, atau gunakan token acak kuat yang
  terpisah dari nomor order.
- Batasi data yang ditampilkan pada halaman publik.
- Masking telepon, email, alamat, dan nomor rekening jika tidak diperlukan.
- Tambahkan rate limit pada lookup order.

### BUG-009 — Rate limiting dapat dilewati dan tidak konsisten

- Severity: **Medium**
- Status: **Fixed (2 September 2026)**
- Area: Authentication, public API, deployment

#### Deskripsi

Rate limiter menggunakan `Map` dalam memory setiap proses, sedangkan PM2
menjalankan dua worker cluster. Bucket limit tidak dibagikan antar-worker dan
hilang ketika proses restart.

Aplikasi juga memakai nilai pertama `X-Forwarded-For`, sementara Nginx
mempertahankan nilai header dari client. Penyerang dapat mengganti header tersebut
untuk memperoleh bucket IP baru.

#### Bukti kode

- `lib/rate-limit.ts:5-15`
- `lib/rate-limit.ts:64-81`
- `ecosystem.config.js:35-38`
- `deploy/nginx.conf:70-73`

#### Rekomendasi

- Gunakan shared store seperti Redis.
- Hanya percaya header dari reverse proxy yang dikenal.
- Konfigurasikan Nginx untuk menimpa IP client atau parse trusted proxy chain
  dengan benar.

### BUG-010 — Open redirect pada login/register member

- Severity: **Medium**
- Status: **Fixed (2 September 2026)**
- Area: Member authentication

#### Deskripsi

`callbackUrl` dari query string langsung digunakan oleh server `redirect()` dan
client router tanpa memastikan URL merupakan path lokal.

#### Contoh

```text
/site/demo/member/login?callbackUrl=https://attacker.example
```

#### Bukti kode

- `app/site/[workspaceSlug]/member/login/page.tsx:28-30`
- `app/site/[workspaceSlug]/member/register/page.tsx:28-30`
- `components/member/member-auth-form.tsx:42-67`

#### Rekomendasi

- Terima hanya relative path yang diawali `/` tetapi bukan `//`.
- Tolak protocol, hostname, backslash, dan URL yang gagal diparse.
- Gunakan helper validasi callback yang sama untuk seluruh login flow.

### BUG-011 — Port PM2 dan Nginx tidak konsisten

- Severity: **Medium**
- Status: **Fixed (2 September 2026)**
- Area: Deployment

#### Deskripsi

PM2 menjalankan Next.js pada port `3011`, tetapi contoh konfigurasi Nginx
meneruskan request ke port `3000`. Deployment yang mengikuti kedua file tersebut
akan menghasilkan `502 Bad Gateway`.

#### Bukti kode

- `ecosystem.config.js:31-46`
- `deploy/nginx.conf:52-67`

#### Rekomendasi

- Gunakan port yang sama pada PM2, Nginx, dokumentasi, dan health check.
- Jadikan port environment variable tunggal agar tidak terjadi konfigurasi
  ganda.

### BUG-012 — Endpoint Meta CAPI dapat menerima event palsu

- Severity: **Medium**
- Status: **Fixed (2 September 2026)**
- Area: Meta Pixel/CAPI analytics

#### Deskripsi

Endpoint publik menerima `workspaceId`, event name, event ID, purchase value, dan
order ID dari client. Event tidak diverifikasi terhadap page, order, enrollment,
atau transaksi yang benar-benar ada. Pihak luar dapat mengirim Lead atau Purchase
palsu dan merusak optimasi iklan workspace.

#### Bukti kode

- `app/api/meta/event/route.ts:15-55`
- `app/api/meta/event/route.ts:57-77`
- `app/api/meta/event/route.ts:80-131`

#### Rekomendasi

- Kirim event transaksi penting dari server berdasarkan record database.
- Untuk event browser, gunakan signed page/event token dengan masa berlaku
  singkat.
- Jangan menerima `value`, `order_id`, atau jenis Purchase secara bebas dari
  client.

## Hasil Remediasi 2 September 2026

- Claim customer lama sekarang memerlukan OTP email sebelum password dan profil
  dapat diubah. Enrollment dan membership baru juga memerlukan member session.
- LMS memeriksa customer, workspace, dan status `ACTIVE` pada halaman lesson dan
  server action progress.
- Upload form dideteksi melalui magic bytes, dipaksa ke ekstensi aman, disimpan
  di storage privat, dan diunduh melalui endpoint berotorisasi sebagai attachment.
- Rich HTML memakai sanitizer parser allowlist saat disimpan dan saat dirender.
- Quote ongkir dihitung ulang dari produk, quantity, berat database, destination,
  courier, dan service pada server.
- Payment create memerlukan signed access token, memiliki rate limit, dan hanya
  mengizinkan simulasi dengan flag development eksplisit.
- Transisi payment dan fulfillment berjalan dalam transaksi `Serializable`.
  Stok serta kupon memakai conditional update, sedangkan referral dan komisi
  memiliki unique constraint per order.
- Detail order dan halaman status payment memerlukan signed access token.
- Rate limit memakai bucket PostgreSQL bersama; Nginx menimpa header IP client
  dan PM2 mengaktifkan trusted proxy secara eksplisit.
- Callback member dibatasi ke relative same-origin path, port deployment menjadi
  konsisten di `3011`, dan browser Meta CAPI event memerlukan signed event token.

Validasi setelah remediasi:

- `pnpm exec tsc --noEmit`: berhasil.
- `pnpm test`: 131 test berhasil pada 17 test file.
- `pnpm lint`: berhasil; tersisa satu warning optimasi gambar non-blocking.
- `pnpm build`: berhasil.
- 44 migration berhasil diterapkan dari database kosong.
- Prisma migration diff terhadap schema: kosong (tidak ada drift).
- Smoke test lokal `GET /`: HTTP 200.
